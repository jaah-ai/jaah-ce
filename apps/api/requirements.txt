# multipart/form-data parsing for FastAPI's UploadFile (task attachment uploads, app/routes/attachments.py).
# Pinned >=0.0.18 — CVE-2024-53981 (GHSA-59g5-xgcq-4qw3, a malformed-boundary DoS) affects earlier releases.
#
# AND >=0.0.31 — PYSEC-2026-3040. `parse_form()` did not validate `Content-Length`, so a NEGATIVE value
# turned its bounded read into a read-until-EOF. Verified at the source rather than taken from the
# advisory: 0.0.31 adds `if content_length < 0: raise ValueError(...)`, which 0.0.20 does not have.
#
# THIS IS DEFENCE IN DEPTH, NOT A LIVE HOLE HERE, AND THE FIRST DRAFT OF THIS COMMENT SAID OTHERWISE.
# It claimed the vulnerable parser sat above `routes/attachments.py::_read_bounded` and had therefore
# made that helper's memory bound void. That is FALSE, and a blind review caught it: the pinned
# starlette (0.40.0) never calls `parse_form()` at all — `formparsers.py` drives `MultipartParser`
# directly and spools each part into a `SpooledTemporaryFile`. So the CVE's entry point is unreachable
# from this app today, `_read_bounded` was doing its job the whole time, and what the bump buys is
# closing the path before some future starlette takes it. Recorded because the wrong version of this
# sentence would have become the cited precedent for the next person reasoning about upload limits.
#
# ONE REAL BEHAVIOUR CHANGE, MEASURED, because "no behaviour change" was also wrong. From 0.0.30 a part
# carrying ONLY the RFC 5987 extended form (`filename*=UTF-8''...`) with no plain `filename` no longer
# yields a `filename` option:
#     0.0.20  filename*-only -> {name, filename}
#     0.0.31  filename*-only -> {name}
# starlette builds an `UploadFile` only `if b"filename" in options`, so such a part arrives as a plain
# form field and `file: UploadFile = File(...)` answers 422 — landing exactly on the non-ASCII filename
# case `attachments.py` exists to serve. Browsers and requests/httpx send the plain spelling, and a part
# carrying BOTH still resolves, so the blast radius is a client that sends `filename*` alone. Named
# rather than discovered. (Security-neutral-to-positive: where both are present the ASCII one now wins,
# so the BIDI-override stripping downstream sees the tamer value.)
